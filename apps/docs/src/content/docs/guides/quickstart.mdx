This walks you from a fresh clone to a real authenticated request against your own running API. No prior knowledge of the codebase is needed — follow it top to bottom.

By the end you will have the stack running locally, a user account, and an access token you can use on any endpoint.

## Before you start

You need [Docker](https://www.docker.com/) 29+ with Compose, and [pnpm](https://pnpm.io/) 11+. Everything else runs inside containers.

## Get the API running

<Steps>

1. Clone the repository and enter it:

   ```bash
   git clone https://github.com/JosepRivera/overload-server.git
   cd overload-server
   ```

2. Create your environment file:

   ```bash
   cp .env.example .env
   ```

   Fill in `POSTGRES_USER`, `POSTGRES_PASSWORD`, `POSTGRES_DB`, `PORT` and `JWT_SECRET`. The rest have working defaults — see [Environment Variables](https://github.com/JosepRivera/overload-server#environment-variables) for the full table.

3. Start the stack:

   ```bash
   pnpm dev:build
   ```

   Use `dev:build` the first time — it installs dependencies and builds the images. Afterwards `pnpm dev` is enough.

   Three containers come up: PostgreSQL, the API, and this documentation site. Pending migrations are applied automatically on startup.

4. Confirm the API answers:

   ```bash
   curl http://localhost:3000/api/docs
   ```

   You should get HTML back — that is the interactive API reference.

</Steps>

<Aside type="tip">
Open <a href="http://localhost:3000/api/docs" target="_blank">the interactive reference</a> in a browser. Every endpoint below can also be run from there with a button.
</Aside>

## Make your first request

<Steps>

1. Register a user. This returns tokens immediately — no separate login step needed:

   ```bash
   curl -X POST http://localhost:3000/auth/register \
     -H "Content-Type: application/json" \
     -d '{
       "email": "you@example.com",
       "name": "Your Name",
       "password": "at-least-8-chars"
     }'
   ```

   The response wraps everything in `data`:

   ```json
   {
     "data": {
       "user": { "id": "…", "email": "you@example.com", "name": "Your Name" },
       "accessToken": "eyJhbGciOi…",
       "refreshToken": "eyJhbGciOi…"
     }
   }
   ```

2. Save the access token to a shell variable so you can reuse it:

   ```bash
   export TOKEN="paste-your-accessToken-here"
   ```

3. Call an authenticated endpoint:

   ```bash
   curl http://localhost:3000/users/me \
     -H "Authorization: Bearer $TOKEN"
   ```

   If you get your own profile back, authentication works.

</Steps>

<Aside type="caution" title="Access tokens expire in 15 minutes">
When a request starts returning `401`, your access token has expired. Do not log in again — use the refresh token instead. The [Authentication guide](/guides/authentication/) covers the full rotation flow.
</Aside>

## Create something real

One last step, so you have data to work with.

<Aside type="tip" title="Shortcut: seed exercises">
If you do not want to create them by hand, run `pnpm db:seed` to load a set of predefined exercises (one per category) and skip the step below.
</Aside>

Create an exercise:

```bash
curl -X POST http://localhost:3000/exercises \
  -H "Authorization: Bearer $TOKEN" \
  -H "Content-Type: application/json" \
  -d '{
    "name": "Bench Press",
    "category": "chest",
    "type": "compound"
  }'
```

Keep the returned `id` — you will need it to log sets.
